# MARC Camden & Brunswick Line GTFS

An unofficial GTFS feed for the MARC Camden and Brunswick Lines, weekday-only,
covering the service change effective 2026-09-28 (the new Brunswick↔Camden
through-running trains 830/831), built from the PDFs in `source-pdf/`.

See [`PLAN.md`](PLAN.md) for the full design, the reasoning behind every
non-obvious decision, and the running TODO / future-work list.

## Building

Requires [pixi](https://pixi.sh) (Python + poppler, from conda-forge) and
[cargo](https://www.rust-lang.org/tools/install) (the optional validator).

```sh
make all      # test + build + validate
make build    # just build/marc-camden-brunswick-gtfs.zip
```

Other targets:

- `make test` — unit tests for the timetable-parsing/AM-PM-resolution logic
- `make render-pdfs` — render every source PDF page to PNG (`build/pdf-preview/`),
  for checking a cell in `extracted/*.csv` against the actual brochure by eye
- `make extract-draft` — re-run PDF extraction into `extracted/*.draft.csv`
  (never overwrites the reviewed `extracted/*.csv` -- see below)
- `make diff-sources` — cross-check the two independently-extracted timetable
  sources (the brochure vs. the "Changes" PDF) against each other

## Repository layout

- `source-pdf/` — raw inputs (the four MARC PDFs, plus a pre-2026-09-28 GTFS
  export used as a source for station coordinates). Never modified.
- `reference/` — station coordinates/accessibility and agency info, derived
  once from `source-pdf/` and then hand-maintained (see `gtfs_builder/build_reference.py`).
- `extracted/` — the timetables themselves, pulled from the PDFs and manually
  verified cell-by-cell against the rendered pages before being trusted.
- `gtfs_builder/` — the Python pipeline: PDF extraction, the extraction cross-
  check, and the GTFS builder itself.
- `validator/` — a small Rust crate (`gtfs-structures`) that round-trip-parses
  the built feed and checks referential integrity as a final sanity check.
- `build/` — everything generated by `make` (gitignored).

## Known limitations

See PLAN.md §9 ("Future / not now") for the full list -- notably: no
`shapes.txt` yet, the contingency "R" schedule's real (unpublished) extra
stops aren't modeled, and Columbus Day (2026-10-12) is treated as a regular
weekday pending MARC publishing its promised modified schedule.
